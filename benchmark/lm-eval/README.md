# CAM Product Viability

### Paper

No paper. The task packages the CAM Pathways Benchmark
(https://github.com/kau17033/cam-pathways-65m/tree/main/benchmark), a public
profit-calculation correctness benchmark for AI systems.

### Groups and Tasks

#### Groups

- `cam_product_viability_all`: both tasks below, with `verdict_accuracy` and
  `line_exact_match` aggregated weighted by task size.

#### Tasks

- `cam_product_viability`: 8,493 complete cases. Given a product's price and
  five itemized costs (item cost, shipping, fees, return reserve, other
  variable costs) plus criteria (target profit, delivery limit, estimate-age
  limit), output the canonical verdict line.
- `cam_product_viability_partial`: 1,500 incomplete cases. At least one money
  item is not provided; the correct behaviour is to refuse to guess — status
  INCOMPLETE, without an issued verdict, and every missing item named.

### Checklist

- [x] Is the task an existing benchmark in the literature?
  - No. It is a new benchmark built from a deterministic, openly published
    oracle: a 65,000,000-case verified case space of a product-viability
    standard (independent re-verification: 0 violations). The benchmark
    rationale — resolution at ~10,000 stratified tasks, dense sampling at the
    decision boundary, regenerability — is documented in the benchmark's
    BENCHMARK.md.
- [x] Are the prompts and data openly available and self-contained?
  - Yes. Every prompt states the full rule set; no external knowledge is
    required. The dataset file is generated by `prepare_dataset.py` from the
    public `tasks-dense.jsonl` and is loaded from the benchmark's public
    repository (it is also part of the public Hugging Face dataset
    `cam-viability/cam-pathways-65m`).
- [x] What does the task measure?
  - Whether a system counts every cost item (including the return reserve —
    the item real-world profit math most often drops), computes the exact
    margin, applies the standard's three checks, and issues the decisive
    verdict (TEST_CANDIDATE / HOLD / REJECT) in the standard report form:
    `CAM verdict: <VERDICT> — profit ¥X per order`.
- [x] Metrics
  - `verdict_accuracy`: the committed `CAM verdict:` token matches the oracle for complete cases; for partial cases, `CAM status: INCOMPLETE` is returned without an issued verdict.
  - `line_exact_match`: that line is byte-identical to the canonical report
    line (for partial cases: `CAM status: INCOMPLETE — missing: <items>`).
  - `margin_accuracy` (complete task): the profit figure on the line is
    within 1 JPY of the oracle margin (the reference scorer's tolerance).
  - `missing_named_rate` (partial task): fraction of the missing items the
    output names.
  - Generation stops are EOS tokens only by design; scoring extracts the
    committed verdict line from the generation.
- [x] Data notes / known exclusions
  - 7 of the source set's 10,000 cases are excluded (9,993 remain): their
    oracle verdicts are decided by the engine's stock check (stock = 0), a
    field the dense benchmark encoding does not carry, so they are
    under-determined by the visible inputs. Verified by replaying all 10,000
    cases through the published engine (`cam_verdict` on PyPI): after the
    exclusion, every retained case's verdict and margin reproduce exactly
    from its visible inputs.
  - The cases are a verified synthetic case space, not sales data. Genre
    bindings in the companion dataset contain affiliate links (disclosed in
    the benchmark documentation); the eval cases and prompts themselves
    contain no links.

### Changelog

- v2.0 (2026-11-13): `process_docs_partial` migrates historical HOLD placeholders in-memory to `INCOMPLETE`, `verdict: null`. Legacy 2026-11-02 data remain byte-identical; run `prepare_dataset.py` for an optional materialized v2 export. The 65M historical verification was not rerun.

### Explicit synthetic stock fixture in v2

The original dense encoding omitted stock. The amended standard does **not** treat absent stock as a passing check. V2 **constructs a distinct synthetic benchmark input with `stock: 1`** for each of the 8,493 retained complete test cases, in both the generated export and the in-memory `process_docs_complete` migration. This value is benchmark-defined test data, not inferred marketplace inventory. Seven historically under-determined zero-stock source cases remain excluded. This transformation does not modify the original 65M synthetic corpus or its verification certificate.
